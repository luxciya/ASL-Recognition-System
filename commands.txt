**Sign Language Recognition System using Computer Vision and Machine Learning**

## 3️⃣ Why MediaPipe is Used

### Problem with raw images

* Sensitive to lighting
* High computation
* Slower real-time performance

### MediaPipe Solution

* Detects **21 landmarks per hand**
* Each landmark has `(x, y, z)` coordinates
* Works fast and accurately

### Landmark Advantage

* Converts images into **numerical data**
* Makes ML models **lighter and faster**

---

## 4️⃣ Hand Landmark Structure

### One Hand

* 21 landmarks
* Each landmark → `(x, y, z)`

👉 Total values per hand:

```
21 × 3 = 63 values
```

### Two Hands

```
2 × 21 × 3 = 126 values
```

---

## 5️⃣ Two-Hand Detection & Ordering

### Why two hands?

* Many ASL signs use **both hands**

### Fixed ordering (VERY IMPORTANT)

To avoid confusion during ML training:

```
Left hand landmarks → Right hand landmarks
```

If a hand is missing:

* Fill that hand’s data with **zeros**

This ensures:

* Always **126 input values**
* Stable model training

## 7️⃣ Why Dataset Conversion Was Needed

### Kaggle dataset provides:

❌ Images

### Our project uses:

✅ MediaPipe landmarks

### Solution:

We **converted images → landmarks**

This created a dataset that:

* Matches real-time camera input
* Is ML-ready
* Is efficient

---

## 8️⃣ Dataset Conversion Process (Pipeline)

### Step-by-step flow:

```
Image → MediaPipe Hands → Landmarks (x,y,z) → CSV
```

### For each image:

1. Load image using OpenCV
2. Convert BGR → RGB
3. Detect hands using MediaPipe
4. Extract landmarks
5. Separate Left & Right hand
6. Combine into 126 values
7. Append label (A–Z)
8. Save to CSV

---

## 9️⃣ CSV Dataset Structure

### One Row in CSV

```
x1, y1, z1, x2, y2, z2, ... x126, LABEL
```

Example:

```
0.45,0.62,-0.01,...,0.33,A
```

* First **126 columns** → landmark features
* Last column → **label (sign letter)**
